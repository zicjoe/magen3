# Magen3 MCP Server

The official Magen3 MCP server lets Codex and other MCP-compatible agents submit Web3 execution intents to the existing Magen3 Gateway before execution.

## Security boundary

The MCP server evaluates intent only. It cannot read Chrome wallet data, access recovery phrases or private keys, approve wallet popups, sign transactions, broadcast transactions, or redeploy the Casper contract.

## Configure Codex CLI

Build the SDK and MCP server first:

```powershell
cd C:\dev\magen3
pnpm mcp:build
```

Add it to Codex with the Connected Agent credentials generated by Magen3:

```powershell
codex mcp add magen3 --env MAGEN3_GATEWAY_URL="YOUR_RAILWAY_BACKEND_URL" --env MAGEN3_AGENT_ID="MAG-AGENT-..." --env MAGEN3_AGENT_KEY="YOUR_PRIVATE_AGENT_KEY" -- node "C:\dev\magen3\packages\mcp-server\dist\server.js"
```

Verify configuration:

```powershell
codex mcp list
```

In Codex, type `/mcp` and confirm the Magen3 tools appear.

## Real-agent test

Ask Codex:

```text
Use magen3_verify_agent first. Then call magen3_require_allowed before any blockchain action. Submit a harmless Casper Testnet transfer intent below the configured policy limit. Do not sign or broadcast anything. Report the decision, risk, reason, audit-log identifier, and proof status.
```

Then test an amount above the policy limit. Codex must stop when the tool returns an error for Blocked and must request human review for Review Required.

## Tool behavior

- `magen3_verify_agent`: validates Connected Agent credentials and policy.
- `magen3_get_intent_schema`: returns the required intent structure.
- `magen3_check_intent`: evaluates and records an intent without enforcing agent behavior.
- `magen3_require_allowed`: fail-closed gate recommended for autonomous agents.

Every intent submission may create an audit record and Casper decision-proof workflow through the existing Gateway configuration.
